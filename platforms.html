Setup guide

Getting the charts working on your platform

Every chart does the same thing: it finds a table or grid on the same page by its column headers, reads the rows and draws itself. So it works anywhere you can put a table and a script on one page – and with a little glue code where the platform hands you data instead of a page.

Which platforms work

PlatformFitHow
MicroStrategyWorks as-isHTML container in a dossier or document, with the grid on the same page. Add the two class names so big grids are read in full. Tested.
Any web page / intranetWorks as-isAny page that lets you add HTML and JavaScript next to a table – an intranet page, a static report, a CMS block. Tested (it's how the demos on this site run).
TableauWith an extensionA dashboard extension reads the worksheet's summary data, writes it to a table and loads the chart. Needs the extension allowed on your Server/Cloud site. Not tested.
LookerWith a custom visualizationA custom visualization receives the query results, writes them to a table and loads the chart. Needs an admin to register it. Not tested.
Power BIOnly as a custom visualPower BI doesn't run JavaScript from HTML in a report, and visuals can't read each other. You'd package the chart into a custom visual (pbiviz) – more work, not tested.
Qlik SenseWith an extensionSame pattern as Looker: an extension gets the hypercube data, writes a table and loads the chart. Not tested.
The chart scripts are tested on MicroStrategy and plain web pages. The Tableau, Looker, Power BI and Qlik routes follow each platform's documented extension model, but haven't been tested here – treat the code below as a starting point.

The three things every setup needs

  1. A table or grid with the right headers. Each chart page lists its default headers (Date, Metric 1, Units …). Use those names, or map your own with data-columns.
  2. A placeholder – <div data-chart-embed="chart-id"> – where the chart should appear.
  3. The script loader from the chart's page, which loads the pinned, integrity-checked script.

MicroStrategy

  1. On the dossier or document page, add a grid with the chart's columns. Keep it on the same page, tuck it behind the chart and make it tall – MicroStrategy only draws the page you're on, and only the rows on screen.
  2. Add an HTML container, choose HTML Text, and paste the snippet. Map your header names with data-columns.
  3. Add data-grid-class="mstrmojo-Xtab" and data-scroll-class="mstrmojo-scrollNode" so the chart can scroll through big grids and read every row.
  4. View it in presentation mode. Point filters and selectors at the grid – the chart follows the grid.
MicroStrategy – HTML container (example: Time Series Trio)
<div data-chart-embed="time-series-trio"
     data-columns='{"date":"Day","v1":"Revenue","v2":"Orders","v3":"Conversion Rate"}'
     data-grid-class="mstrmojo-Xtab" data-scroll-class="mstrmojo-scrollNode"
     style="height:100%"></div>
<script>
(function () {
var s = document.createElement("script");
s.src = "https://kaijxnes.github.io/HTML-Charts/charts/time-series-trio-1.1.0.js";

Tableau, Looker, Power BI and Qlik

These platforms don't let a script read other parts of the dashboard, but their extension models hand your code the query results. Write those into a table on the extension's own page, then load the chart as usual.

Shared helper – write rows into a table
// Shared idea for Tableau, Looker and Power BI: write the platform's data
// into a plain HTML table on the same page, then load the chart script.
// The chart reads the table exactly as it reads a dashboard grid.
function writeTable(headers, rows) {
  var t = document.getElementById("grid") || document.body.appendChild(Object.assign(document.createElement("table"), { id: "grid" }));
  t.innerHTML = "<thead><tr>" + headers.map(function (h) { return "<th>" + h + "</th>"; }).join("") + "</tr></thead><tbody>" +
    rows.map(function (r) { return "<tr>" + r.map(function (v) { return "<td>" + v + "</td>"; }).join("") + "</tr>"; }).join("") + "</tbody>";
}

Tableau – dashboard extension

Put a worksheet with the chart's fields on the dashboard (it can be hidden), host this page somewhere your Tableau site allows, and add the extension with a .trex manifest pointing at it.

Tableau extension page
<!-- index.html of a Tableau dashboard extension (.trex manifest points here) -->
<div data-chart-embed="time-series-trio" style="height:100vh"></div>
<script src="tableau.extensions.1.latest.min.js"></script>  <!-- from Tableau's Extensions API download -->
<script>
tableau.extensions.initializeAsync().then(async function () {
  var ws = tableau.extensions.dashboardContent.dashboard.worksheets.find(function (w) { return w.name === "Chart data"; });
  var reader = await ws.getSummaryDataReaderAsync();
  var table = await reader.getAllPagesAsync();
  await reader.releaseAsync();
  writeTable(table.columns.map(function (c) { return c.fieldName; }),
             table.data.map(function (row) { return row.map(function (v) { return v.formattedValue; }); }));
  loadChart();   // the script loader from the snippet
});
</script>

Looker – custom visualization

Host the file and register it under Admin → Visualizations (or in a LookML project manifest). Choose dimensions and measures named like the chart's headers, or map them with data-columns.

Looker custom visualization
// Looker custom visualization (registered in the admin Visualizations page or a LookML manifest)
looker.plugins.visualizations.add({
  create: function (element) {
    element.innerHTML = '<table id="grid" style="display:none"></table>' +
                        '<div data-chart-embed="time-series-trio" style="height:100%"></div>';
    loadChart();
  },
  updateAsync: function (data, element, config, queryResponse, details, done) {
    var f = queryResponse.fields.dimension_like.concat(queryResponse.fields.measure_like);
    writeTable(f.map(function (x) { return x.label_short || x.label; }),
               data.map(function (row) { return f.map(function (x) { return row[x.name].rendered || row[x.name].value; }); }));
    done();
  }
});

Power BI – custom visual

Power BI's HTML visuals don't run JavaScript, so a snippet can't be pasted in. Build a custom visual with the pbiviz tools, bundle the chart script and Chart.js into it, and write the data view into a table in update(). Organisations often need to approve custom visuals before use.

Power BI visual.ts (sketch)
// Power BI custom visual (pbiviz) – src/visual.ts, update()
// Copy the chart script into the visual's source and bundle it: Power BI visuals
// run in a sandbox and shouldn't load scripts from the internet.
public update(options: VisualUpdateOptions) {
  const t = options.dataViews[0].table;
  writeTable(t.columns.map(c => c.displayName),
             t.rows.map(r => r.map((v, i) => formatValue(v, t.columns[i].format))));
}

Troubleshooting

  • "Couldn't find the grid" – a header doesn't match. Check spelling, or map it with data-columns. Matching ignores spaces and capital letters.
  • Only some rows read – the grid only draws what's on screen. Make it taller, and on MicroStrategy add the two class attributes above.
  • Nothing appears at all – the platform may block JavaScript or outside scripts. Ask your admin whether HTML containers can run scripts and whether kaijxnes.github.io is reachable.
  • Wrong numbers – open Read details under the chart to see which headers and how many rows it read.
