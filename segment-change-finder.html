What is a Segment Change Finder?

A segment change finder is a grid of small daily charts, one per combination of two dimensions such as product × segment, coloured by how much each changed in the last week – so the group that moved most stands out, along with whether it was fewer customers or lower spend per customer. This Segment Change Finder is free to copy and paste: it reads a grid on the same page – in a MicroStrategy (Strategy One) dashboard's HTML container, or any web page – and draws itself in the browser, with no plugin, server or data upload.

When to use it

Use it for daily monitoring across products × segments, channels × regions or similar, when the question is 'what moved, and why?'

Questions it answers

  • Which group fell the most this week?
  • Was it fewer customers or lower spend per customer?
  • Is it a sudden drop or a slow slide?

How to use it

  1. On your dashboard page, add a grid with the columns below (or map your own header names – see below). Keep it on the same page – tuck it behind the chart rather than hiding it, and make it tall.
  2. Add an HTML container (one that runs JavaScript) and paste the snippet.
  3. View the page. The chart finds the grid, reads every row and draws itself; it updates when filters change the grid.

Your own column names

The chart looks for the default headers above. If your grid's headers are different, map them by key with data-columns on the placeholder – the chart then shows your names too. data-labels (same keys) changes just the on-screen names, and data-title changes the heading. For grids that draw rows in batches, data-grid-class and data-scroll-class name the grid's container and its scroll box so every row is read.

What it does

  • One tile per combination, red or green by size of change
  • Last 7 days vs the previous 7 days or the previous 4 weeks (data-compare="4wk")
  • Revenue, units or revenue per unit (data-show)
  • Day view: the latest day against the same day last week, with no compare buttons (data-period="day")
  • Headline card names the biggest fall and splits it into fewer units vs lower value per unit
  • Reads dates with or without a year (e.g. data-date-format="DD/MM")
  • Fits its container: cards compact in short boxes, side panels drop in narrow ones
  • No Chart.js needed – drawn as SVG

Data & security

  • Reads only what is drawn on the page for the viewer, so the viewer's normal permissions still apply
  • Calculations happen in the viewer's browser; nothing is uploaded or sent anywhere
  • The only download is this script, integrity-checked
  • No logins, API keys, cookies or browser storage
